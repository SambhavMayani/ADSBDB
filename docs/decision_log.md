# EcoSentinel architecture decisions

Current design, reviewed 24 October 2026; query-input decisions added 28 October 2026. Detailed formats and commands belong in the zone guides. This register explains current choices and costs; Git preserves the earlier decision history.

| Decision | Rationale | Cost or boundary |
|---|---|---|
| Four zones with separate responsibilities | Preserve original bytes, standardise formats, evaluate quality, then encode; each stage can be inspected and retried. | More objects and explicit lineage contracts. |
| S3-compatible storage with Docker | One object API for images, recordings, documents and audit metadata. | Running storage service required; no distributed transaction with Chroma. |
| Optional acquisition with provenance sidecars | Local files and cached models support operation without provider availability. | Exact reproduction requires a data handoff; fresh downloads differ. |
| Hash plus filename as Landing identity | Repeated ingestion of the same bytes/name reuses verified completion state stored with the data. | A renamed file has a new ingest identity. Content-quality duplication belongs in Trusted. |
| Verify copy and marker before optional Temporal cleanup | Recover from partial copy or marker publication without losing input. Retain Temporal by default. | Extra verification reads; cleanup is explicit. |
| Pre-ingestion Security Gate | Check supported extensions, byte signatures, image structure, archive expansion and resource ceilings before upload. | Bounded screening is not antivirus scanning or proof of harmlessness. |
| RGB JPEG, FLAC PCM16, UTF-8 text | Predictable decoders and modality-specific processing, with raw hashes and source references. | JPEG is lossy; first-frame MPO conversion omits secondary frames from Formatted. Landing retains originals. |
| Conservative Trusted policies | Reject technical violations and confirmed duplicates; keep dark images, possible overlays and quiet recordings as warnings. | Heuristics miss near duplicates or flag natural text; thresholds are operational choices. |
| Separate safety and quality budgets | Stricter Trusted ceilings bound accepted representations: images 20 decimal MB / 40 MP / minimum 128 by 128; audio 200 MB; text 4 MB. | These limits do not measure ecological value or guarantee fixed peak RAM. |
| Modality-specific duplicate scope | Exact audio/text across species may be meaningful or expose label conflicts; image candidates need strict confirmation. | Full runs are needed for global duplication; cropped variants can survive. |
| Retain prior accepted bytes after later error/rejection | Avoid destructive policy re-evaluation; current manifests control eligibility for new indexing. | Retirement candidates require review; historical bytes are not automatically current accepted evidence. |
| Five explicit Chroma vector spaces | CLIP aligns images/text, CLAP aligns sounds/text, multilingual E5 small handles compact text retrieval. | General-purpose models are not specialist classifiers; no labelled comparison proves optimality. |
| Segment identities and policy fingerprints | Verify exact part coverage and compatibility before reuse; recover partial publication. | Equal dimensions or matching counts do not establish compatibility. |
| CPU, bounded batches, sequential encoder processes | Operate on the authors' Windows hardware without CUDA. | Latency depends on length, cache and RAM. |
| Independent query snapshot | Chroma already persists vectors on disk. We additionally copy/hash-verify the database for queries to protect the audited original from client migrations/internal writes. This is a project preservation policy, not a persistence requirement. | Extra database disk space; stop writers and refresh to a new directory after data changes. Source media are not copied and embeddings are not recomputed. Coordinated single-index access is an alternative. |
| Asset grouping, diversity quotas, RRF | Avoid long-file dominance, expose modalities and combine rankings without mixing cosine scales. | Quotas alter raw order; similarity and RRF are not species probabilities. |
| Local Qwen 2.5 3B Q4_K_M RAG with E5/CLIP and optional BLIP | Generate from bounded retrieved text, fixed revision/hash, on CPU. | Qwen receives text rather than pixels; captioning, retrieval and interpretation can fail. |
| Vocabulary domain gate before RAG retrieval | Stop clearly unrelated requests (pizza, cars) before retrieval and the CPU-expensive generator; a word list is deterministic, inspectable and needs no extra model or uncalibrated similarity threshold. Plurals and common BLIP words are accepted since 28 October 2026 ("dogs" was rejected). | Not a calibrated out-of-distribution detector: false rejections surface as explicit abstention; it depends on BLIP's caption. |
| Restricted evidence IDs and post-generation validation | Resolve literal quotations server-side and distinguish answer, partial answer, abstention and error. | Literal quotations do not prove semantic entailment or species identity. |
| Sequential orchestration, locks, timeouts, atomic reports | Make failures observable and retries safe at each boundary. | Recovery verifies state across stores; there is no global all-or-nothing transaction. |
| One requirements file and layered CI | One dependency contract; offline Windows/Linux checks and separate storage integration. | Native acceptance needs cached weights/RAM outside ordinary CI; verify the submitted commit remotely. |
| External queries prepared like the corpus, in memory | Reuse the Formatted conversions and Trusted measurements so query and stored vectors are comparable; never store the query. See the section below. | Tasks import zone functions; warnings are heuristics. |

## Query inputs: same processing, without the zones

**Context.** An uploaded image or recording, or a typed query, previously went straight to the encoder. The indexed corpus, however, had passed through Formatted and Trusted. We asked the supervisor whether query inputs should pass through the pipeline. His answer, summarised: the processing applied to stored data should, as a general convention, also be applied to query data so that the similarity comparison is fair (for example, the same image as PNG or JPEG can produce different embeddings); this does not require passing through the zones or storing anything, and a separate pipeline reusing the needed code is appropriate; processes that could alter what the user asks may be skipped when the choice is justified.

| Decision | Rationale | Cost or boundary |
|---|---|---|
| One in-memory query pipeline, `multimodal_tasks/query_preparation.py`, used by Tasks 1, 2 and 3 | It imports the zone functions instead of copying them, so shared conversion rules have one implementation. Tests verify that each public Task path uses it. | Tasks depend on Formatted/Trusted functions, in the same direction as Exploitation already depends on upstream contracts. Moving them to a shared package would be cleaner but would refactor the validated pipeline. |
| Do not ingest or index uploaded queries | Zones build the dataset; an uploaded query is ephemeral. Retrieval still reads the existing query snapshot, and stored-image selection may read existing Trusted media. Storing it would mix unverified user input with the corpus and could later return the query as its own result. | An input SHA-256, preparation steps, selected metrics and warnings return in the response. The bytes are not persisted. A user-requested RAG JSON export may retain that report, without the image. |
| Apply the Formatted conversions exactly | Images: `convert_to_jpeg` (RGB, white beneath transparency, JPEG quality 95, first frame). Audio: `convert_audio` to FLAC PCM16, keeping rate and channels. Text: `to_canonical_text` (UTF-8, NFC, LF, no control characters), then stripped like indexed chunks. | Conversion can change decoded values, including for JPEG inputs; the vector/quality effect has not been measured in this review. Transparent PNG/WebP and higher-precision audio make the policy difference particularly clear. JPEG remains lossy, as in the corpus. |
| Reuse Trusted measurements as non-blocking warnings | `analyze`/`image_rejection` and `audio_metrics` use the Trusted YAML thresholds. Blur, darkness, little colour, unusual aspect, small size, very short, quiet, silent, clipped or DC-offset audio produce a warning; these quality signals do not block retrieval. Invalid files and mandatory resource limits still block the request. Corpus rejections (under 128 px, under 0.01 s) also become warnings. A poor query can still contain what the user wants: poor query, possibly poorer results, but the user decides. | Heuristic signals, not calibrated quality scores. Text warnings (short document, PII patterns) are not meaningful for a question and are not applied. |
| Do not reuse the watermark heuristic for queries | It flags 32 of 100 reference images, without labelled precision/recall validation. An overlay need not prevent retrieval. | A real watermark in a query is not reported. |
| Show warnings in the interface and response, not in Qwen's prompt | Quality measurements describe the input rather than biological evidence. Keeping them outside the constrained evidence prompt avoids confusing those roles; the response and interface display warnings directly. The effect on abstention rates has not been measured. | The generated sentences do not mention image quality. |
| Reuse a stored Trusted image byte for byte | It is already the canonical JPEG that was indexed; re-encoding would move it away from its own vector. | Applies to RAG images selected from the corpus. |
| Accept the formats of the Formatted Zone | Images: JPEG, PNG, WebP, MPO, BMP, GIF and TIFF, in the interface and the server. Audio: only formats the Formatted converter decodes in memory through libsndfile (WAV, FLAC, OGG/Opus, AIFF, CAF and MP3 when the library supports it), because its ffmpeg path needs temporary files and queries must stay in memory. | M4A, AAC, WMA, WebM, AMR and AC3 queries are rejected with an explicit message, although the corpus pipeline accepts them. |
| Shared query safety limits | `validate_query_media` checks 10 MiB, 20 MP, 30 seconds and eight audio channels before conversion, including direct CLI/Python calls. | These are operational bounds, not quality scores or a fixed peak-RAM guarantee. |
| Invalid uploads are client errors | Undecodable files now return HTTP 400 with a clear message instead of a misleading 503 "service unavailable". | The server still does not replace an antivirus. |

Tests: `tests/test_query_preparation.py` checks identity with the Formatted output, warnings instead of rejections, byte-for-byte reuse of Trusted images, that warnings never reach the prompt, accepted/rejected formats and HTTP status codes, using synthetic inputs and model doubles, including a temporary loopback HTTP server. They do not access production storage or download models.

## Interpreting evidence

Quality manifests carry source keys, status, reason, metrics and policy information. HTML, CSV, JSON and plots make decisions reviewable. Provenance completeness measures populated fields, not independent verification of truth or licences. Distribution comparisons reveal changes caused by filtering; unchanged distributions do not establish absence of bias.

The RAG timeout correction is general: incomplete output remains a technical error, context and evidence are bounded, and multipart questions have distinct evidence slots. No answer is hard-coded for the frog example. See [Task 3](generative_tasks_documentation.md) and [validation](testing_and_validation.md).

## Exact-search threshold and focused validation (29 October 2026)

The existing search path scans all eligible vectors when the filtered count is at most 64, and delegates to Chroma HNSW at 65 or more. The cap keeps fallback work small and supports tiny segments without a persisted HNSW reader. It is not a benchmarked optimum. At dimension 512, 64 float32 vectors contain 128 KiB of vector payload, excluding metadata and runtime overhead. Future tuning should compare latency and recall rather than infer optimality from that size.

The delivery review adds 32 storage/recovery/search boundary tests without changing production behaviour. Offline statement coverage rises from 68.17% to 72.37% with the same denominator. The purpose is to verify preservation and failure detection, not to maximise a percentage by excluding code. The report and presentation use the new measured result and keep earlier integration/native evidence separately dated.
